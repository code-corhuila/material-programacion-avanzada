Introducción

En esta sección trabajarás en un proyecto full-stack real utilizando tecnologías modernas de la industria. A cada equipo se le asignará uno de los 15 proyectos disponibles y lo desarrollará de principio a fin, cubriendo backend (API REST), frontend (interfaz de usuario) y base de datos, todo orquestado con Docker.

Objetivo General

Desarrollar una aplicación web full-stack funcional aplicando principios de arquitectura limpia, buenas prácticas de desarrollo, control de versiones con Git/GitHub e integración de servicios mediante contenedores Docker.

Stack Tecnológico del Proyecto

NestJS (Backend)

Framework progresivo de Node.js para construir APIs REST escalables y eficientes con TypeScript, arquitectura modular e inyección de dependencias.

Next.js (Frontend)

Framework de React para producción con renderizado del lado del servidor (SSR), generación estática (SSG) y rutas API integradas.

PostgreSQL (Base de Datos)

Sistema de gestión de bases de datos relacional robusto, confiable y de código abierto con soporte avanzado para consultas complejas.

Docker (Contenedores)

Plataforma de contenedores que permite empaquetar, distribuir y ejecutar aplicaciones en entornos aislados y reproducibles.

Prisma (ORM)

ORM de nueva generación para Node.js y TypeScript que facilita el acceso a la base de datos con un esquema declarativo y migraciones automáticas.

GitHub (Versionamiento)

Plataforma de control de versiones para gestionar el código fuente, ramas, pull requests y colaboración en equipo.

Arquitectura del Proyecto

Todos los proyectos siguen una arquitectura en capas con desacople de responsabilidades, orquestada con Docker Compose. Cada capa tiene una función específica y no debe conocer los detalles internos de las demás.

Principio de Separación de Responsabilidades

Controller (recibe la petición HTTP) → Service (lógica de negocio) → Repository (acceso a datos vía Prisma). Cada capa se comunica solo con la siguiente, nunca se salta niveles. Los DTOs validan la entrada, las Entities representan el dominio y los Mappers transforman datos entre capas.

Controller

Recibe peticiones HTTP, valida los datos de entrada con DTOs (class-validator) y delega al Service. No contiene lógica de negocio.

Service

Implementa la lógica de negocio, reglas de validación y orquestación. Llama al Repository para obtener o persistir datos. No conoce HTTP ni Prisma directamente.

Repository

Encapsula el acceso a datos usando Prisma Client. Traduce operaciones del dominio a queries de base de datos. No contiene lógica de negocio.

DTOs, Pipes & Guards

Los DTOs validan la forma de los datos. Los Pipes transforman valores. Los Guards controlan el acceso. Los Filters capturan excepciones globalmente.

Ejemplo de Módulo con Separación de Capas (NestJS)

Cada entidad del proyecto debe seguir este patrón de capas dentro de su módulo:

// ────────────────────────────────────── // dto/create-mascota.dto.ts — Validación de entrada // ────────────────────────────────────── import { IsString, IsInt, IsNotEmpty, Min } from 'class-validator'; export class CreateMascotaDto { @IsString() @IsNotEmpty() nombre: string; @IsString() @IsNotEmpty() especie: string; @IsString() raza?: string; @IsInt() @Min(0) peso: number; }
// ────────────────────────────────────── // repository/mascota.repository.ts — Solo acceso a datos // ────────────────────────────────────── import { Injectable } from '@nestjs/common'; import { PrismaService } from '../../prisma/prisma.service'; import { CreateMascotaDto } from '../dto/create-mascota.dto'; @Injectable() export class MascotaRepository { constructor(private readonly prisma: PrismaService) {} async findAll() { return this.prisma.mascota.findMany({ include: { propietario: true }, }); } async findById(id: number) { return this.prisma.mascota.findUnique({ where: { id } }); } async create(data: CreateMascotaDto) { return this.prisma.mascota.create({ data }); } async update(id: number, data: Partial<CreateMascotaDto>) { return this.prisma.mascota.update({ where: { id }, data }); } async delete(id: number) { return this.prisma.mascota.delete({ where: { id } }); } }
// ────────────────────────────────────── // service/mascota.service.ts — Lógica de negocio // ────────────────────────────────────── import { Injectable, NotFoundException } from '@nestjs/common'; import { MascotaRepository } from '../repository/mascota.repository'; import { CreateMascotaDto } from '../dto/create-mascota.dto'; @Injectable() export class MascotaService { constructor(private readonly mascotaRepository: MascotaRepository) {} async findAll() { return this.mascotaRepository.findAll(); } async findById(id: number) { const mascota = await this.mascotaRepository.findById(id); if (!mascota) { throw new NotFoundException(`Mascota con ID ${id} no encontrada`); } return mascota; } async create(dto: CreateMascotaDto) { return this.mascotaRepository.create(dto); } async update(id: number, dto: Partial<CreateMascotaDto>) { await this.findById(id); // Verifica existencia return this.mascotaRepository.update(id, dto); } async delete(id: number) { await this.findById(id); return this.mascotaRepository.delete(id); } }
// ────────────────────────────────────── // controller/mascota.controller.ts — Solo manejo HTTP // ────────────────────────────────────── import { Controller, Get, Post, Put, Delete, Param, Body, ParseIntPipe } from '@nestjs/common'; import { MascotaService } from '../service/mascota.service'; import { CreateMascotaDto } from '../dto/create-mascota.dto'; @Controller('mascotas') export class MascotaController { constructor(private readonly mascotaService: MascotaService) {} @Get() findAll() { return this.mascotaService.findAll(); } @Get(':id') findById(@Param('id', ParseIntPipe) id: number) { return this.mascotaService.findById(id); } @Post() create(@Body() dto: CreateMascotaDto) { return this.mascotaService.create(dto); } @Put(':id') update(@Param('id', ParseIntPipe) id: number, @Body() dto: CreateMascotaDto) { return this.mascotaService.update(id, dto); } @Delete(':id') delete(@Param('id', ParseIntPipe) id: number) { return this.mascotaService.delete(id); } }
// ────────────────────────────────────── // mascota.module.ts — Ensamblaje del módulo // ────────────────────────────────────── import { Module } from '@nestjs/common'; import { MascotaController } from './controller/mascota.controller'; import { MascotaService } from './service/mascota.service'; import { MascotaRepository } from './repository/mascota.repository'; import { PrismaModule } from '../../prisma/prisma.module'; @Module({ imports: [PrismaModule], controllers: [MascotaController], providers: [MascotaService, MascotaRepository], exports: [MascotaService], }) export class MascotaModule {}

Metodología de Trabajo

Cada equipo debe seguir los siguientes pasos para organizar y desarrollar su proyecto:

1

Asignación del Proyecto

A cada equipo se le asignará uno de los 15 proyectos disponibles. No se repiten proyectos entre equipos.

2

Crear Repositorio en GitHub

Crear un repositorio público o privado en GitHub con la estructura del proyecto. Incluir README.md con la descripción, integrantes y tecnologías.

3

Redactar Historias de Usuario (UH)

A partir de los casos de uso del proyecto, generar Historias de Usuario con el formato: "Como [rol], quiero [acción] para [beneficio]". Documentarlas como Issues en GitHub.

4

Configurar el Entorno con Docker

Crear los archivos Dockerfile y docker-compose.yml para levantar los tres servicios (PostgreSQL, NestJS, Next.js).

5

Diseñar el Esquema de BD con Prisma

Definir las entidades del modelo de datos en schema.prisma, ejecutar las migraciones y generar el cliente Prisma.

6

Desarrollar el API REST (NestJS) con Capas Desacopladas

Para cada entidad, crear un módulo con tres capas separadas siguiendo el principio de responsabilidad única:

  • Controller: Solo recibe peticiones HTTP, valida DTOs y delega al Service.
  • Service: Contiene la lógica de negocio, validaciones y reglas. Llama al Repository.
  • Repository: Encapsula las operaciones de Prisma Client. Es la única capa que accede a la BD.
  • DTOs: Clases con decoradores de class-validator para validar datos de entrada.
  • Common: Filters, Interceptors, Pipes y Guards compartidos entre módulos.
7

Desarrollar el Frontend (Next.js)

Crear las páginas, componentes y formularios que consuman la API. Implementar navegación, listados, formularios y manejo de estado.

8

Integración y Pruebas

Verificar la comunicación entre frontend, backend y base de datos. Realizar pruebas funcionales de los flujos principales.

Contexto del Proyecto

Una institución educativa necesita un sistema integral para gestionar su información académica. Actualmente, el registro de docentes, asignaturas, períodos académicos y la asignación de notas se realiza en hojas de cálculo dispersas, lo que genera inconsistencias, pérdida de información y dificultades para generar reportes de rendimiento. Se requiere una plataforma web que permita registrar estudiantes y docentes, configurar períodos y asignaturas, matricular estudiantes, registrar calificaciones y consultar el historial académico de forma centralizada y confiable.

Casos de Uso

  • CU-01: Registrar estudiante con datos personales, código estudiantil, correo institucional y programa académico.
  • CU-02: Registrar docente con datos personales, título profesional, especialidad y correo institucional.
  • CU-03: Gestionar programas académicos (Ingeniería de Sistemas, Contaduría, Administración, etc.).
  • CU-04: Crear asignaturas con nombre, código, número de créditos y programa al que pertenece.
  • CU-05: Configurar período académico (2026-A, 2026-B) con fecha de inicio y fin.

  • CU-07: Matricular estudiante en una asignatura de un período verificando que no exista duplicidad.
  • CU-08: Registrar calificaciones (nota 1, nota 2, nota 3, nota definitiva) de un estudiante en una matrícula.
  • CU-09: Consultar historial académico de un estudiante con todas sus asignaturas y notas por período.
  • CU-10: Generar reporte de estudiantes matriculados por asignatura y período, con promedio general.
  • CU-11: Listar asignaturas asignadas a un docente en el período actual.

Hoja de Ruta — Sesiones de Clase

1

Configuración del Entorno

Crear repositorio en GitHub, configurar docker-compose.yml con PostgreSQL, servicio de backend (NestJS) y frontend (Next.js). Levantar los contenedores y verificar comunicación entre servicios.

2

Modelo de Datos con Prisma

Definir el schema.prisma con las entidades, relaciones (1:N, N:M), tipos de datos y restricciones. Ejecutar migraciones y generar el Prisma Client. Configurar el PrismaModule en NestJS.

3

Primer Módulo CRUD — Estudiante

Implementar el módulo completo con capas desacopladas: CreateEstudianteDto (validación), EstudianteRepository (acceso a datos), EstudianteService (lógica de negocio) y EstudianteController (endpoints REST). Probar con herramientas como Postman o Thunder Client.

4

Módulos con Relaciones — Asignatura y Matrícula

Crear los módulos de ProgramaAcademico, Asignatura y Matricula aplicando relaciones entre entidades. Implementar validaciones de negocio (no duplicar matrícula, verificar existencia de referencias).

5

Módulos Complementarios — Docente, Período y Calificaciones

Completar los módulos restantes: Docente, PeriodoAcademico, AsignacionDocente y Calificacion. Implementar cálculo de nota definitiva y promedio acumulado.

6

Common Module — Filtros, Interceptores y Pipes

Implementar el módulo common/: HttpExceptionFilter para respuestas de error consistentes, ResponseInterceptor para formato uniforme de respuestas y ValidationPipe global con class-validator.

7

Frontend — Estructura y Listados

Configurar el proyecto Next.js con App Router. Crear el cliente HTTP centralizado (lib/api.ts), los services de cada entidad y las páginas de listado con componentes reutilizables.

8

Frontend — Formularios y Detalle

Implementar formularios de creación y edición con validación del lado del cliente. Crear páginas de detalle, navegación entre vistas y manejo de estados de carga y error.

9

Integración Final y Despliegue

Pruebas de integración de flujos completos (matricular → calificar → consultar historial). Verificar que todo funcione con docker compose up. Revisión de código y buenas prácticas.
